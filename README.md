# FitFuel — Fitness Meal Ordering Platform

A full-stack fitness-food business app for the Egyptian market: a web storefront with macro-labelled meals, a calorie calculator, monthly subscription plans, an installable **mobile app (PWA)** with personalized meal recommendations, and a built-in **admin CRM** — all in one Next.js codebase.

Currency is **EGP**, standard delivery fee is **EGP 30**.

## Features

### Web storefront
- **Menu** — 20+ meals (seeded catalogue) across breakfast, mains, salads and snacks, each labelled with calories, protein, carbs, fat and price
- **Cart & checkout** — persistent cart (localStorage), delivery fee, `FF-####` order numbers, payment method recorded at checkout (cash on delivery / card / wallet)
- **Calorie calculator** — Mifflin–St Jeor BMR → TDEE → goal adjustment (cut / maintain / bulk), with a suggested day of meals
- **Subscription plans** — pick a plan, then choose **exactly N meals per day** (enforced server-side), `FS-####` subscription reference

| Plan | Meals/day | Days/month | Approx. kcal/day | EGP / month |
| --- | --- | --- | --- | --- |
| Duo | 2 | 22 | 1,300 | 5,499 |
| Trio | 3 | 22 | 1,600 | 7,999 |
| Full Day | 4 | 30 | 1,900 | 10,999 |
| Max Performance | 5 | 30 | 2,400 | 13,499 |

### Mobile app (PWA)
- Installable on Android / iOS (`manifest.webmanifest`, standalone display, emerald theme)
- First-run **onboarding** captures weight, height, age, sex, activity level and goal
- **Personalized daily calorie target** (Mifflin–St Jeor) and meal suggestions derived from the saved profile
- Screens: Home, Menu, Plans, Cart, Profile — sharing the same marketplace, checkout and subscription flow as the website
- Open via the **Mobile App** tab or the `/#app` deep link; the installed PWA starts there directly

### Admin CRM
- Order pipeline: pending → confirmed → preparing → delivering → delivered / cancelled
- Client directory with phone-based deduplication
- Product catalogue CRUD
- Subscription management (status, payment, daily meal generation)
- Revenue dashboard with charts and **CSV export** (orders + subscriptions)

## Getting started

### Prerequisites
- [Bun](https://bun.sh) v1.3+ (or Node.js 20+ with npm)
- Python 3 + Pillow — only needed to regenerate the PWA icons

### Setup

```bash
git clone https://github.com/bhamalawi-alt/fitness-food-project-.git
cd fitness-food-project-

bun install

# 1. configure the database URL
cp .env.example .env

# 2. create the SQLite schema
bun run db:push

# 3. seed the products and subscription plans (idempotent upserts)
bun run db:seed

# 4. (optional) regenerate the PWA icons into public/
python3 scripts/make_icons.py

bun dev
```

Open http://localhost:3000 — the **Dashboard** tab opens the admin CRM (no authentication; this is a demo project).

Notes:
- `bun.lock` and `db/custom.db` are not committed. The seed script recreates the full catalogue, and any meals added through the admin UI live in your local database only.
- PWA icons are generated by `scripts/make_icons.py` (emerald rounded square, white "F"). The app runs fine without them, but the install prompt needs them.
- With npm instead of Bun: `npm install`, `npx prisma db push`, then run the seed with a TS runner (e.g. `npx tsx prisma/seed.ts`). On Windows, start the dev server with `npx next dev -p 3000` (the `dev` script pipes logs through `tee`).

## API overview

| Endpoint | Methods | Purpose |
| --- | --- | --- |
| `/api/products`, `/api/products/[id]` | GET, POST, PUT, DELETE | Menu catalogue CRUD |
| `/api/orders`, `/api/orders/[id]` | GET, POST, PATCH | Orders and status transitions |
| `/api/clients` | GET, POST | Client directory (phone dedup) |
| `/api/plans`, `/api/plans/[id]` | GET | Subscription plans |
| `/api/subscriptions`, `/api/subscriptions/[id]` | GET, POST, PATCH | Subscriptions (server validates the exact meal count) |
| `/api/subscriptions/generate-today` | POST | Generates today's orders from active subscriptions |
| `/api/stats` | GET | Revenue and CRM statistics |
| `/api/export`, `/api/export/subscriptions` | GET | CSV exports |

## Data model

`Product` (menu) · `SubscriptionPlan` (catalogue) · `Client` → `Order` → `OrderItem` · `Client` → `Subscription` → `SubscriptionMeal`.

Order items and subscription meals snapshot name, price and macros at purchase time, so later menu edits never corrupt historical records. Deleting a product only nulls the reference (`onDelete: SetNull`).
